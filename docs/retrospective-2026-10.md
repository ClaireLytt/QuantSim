# QuantSim 2026-10 Bug 修复轮复盘

> 范围：13 bug 修复（`4f1d279`）+ 回归套件连带修出的并发死锁（`d7d505e`），共 **14** 个实际缺陷。
> 配套产出：回归用例(84 例)、`docs/bug-knowledge-base.md`、`tools/pr_guard.py`、`docs/release-acceptance.md`。
> 本文档做根因复盘与长期改进，目的是**让同类 bug 不再进第二次**。

---

## 一、Bug 根因归类统计

### 1.1 按根因大类

| 根因大类 | 数量 | 占比 | 案例 |
|---|---|---|---|
| **编码疏漏**（边界/空值/语义近似/判断方式） | 8 | 57% | 短邮箱脱敏、行情除零、擂台 null、游客昵称、mine 通关统计、event 空白、api 中文文案、脱敏身份比对 |
| **架构/设计细节隐患**（事务/并发/状态机/分层） | 5 | 36% | 房间 REQUIRES_NEW、并发注册 TOCTOU、每日死锁(FOR UPDATE 误用)、限流清理竞态、每日一猜落库时机 |
| **测试覆盖不足**（并发路径无测试） | 1 | 7% | 每日双开 500（并发路径从无测试，死锁直到本轮回归才暴露） |

> 注：分类按"修复时改的是哪一层"归主类。多数 bug 是复合的——如"榜单挤位"既是分层设计
> 隐患（过滤该在数据层），也因缺"过滤不挤占名额"的测试而没被拦住。

### 1.2 最该记住的元发现：**近半高危是本轮自己引入的回归**

- "榜单挤位"、"脱敏 isSelf 失效"、"短邮箱脱敏不全" **三个都源于同一次 P1 脱敏改动**
  （`b72ab30`，本会话早先提交）——加脱敏时**没有重审"所有按可见值做判断的逻辑"**，
  也**没有在声称修好前加回归测试**，于是脱敏改动自身成了新 bug 的温床。
- **这是本轮最大的流程教训**：*改动"可见数据/口径"类功能，必须 (a) 全局搜受影响的判断点，
  (b) 加回归测试再声称完成*。知识库 #2、CI 规则 R2 已固化这条。

### 1.3 共性信号

- **并发路径系统性缺测**：注册、每日开局、房间强结、限流——4 个并发点，上线前**零并发测试**，
  本轮一次性补了 1 个并发用例就炸出一个死锁 500。并发是最大的测试盲区。
- **"可见值做判断"反复踩**：username 身份比对（R2）、错误文案子串（R4）——都是"拿展示/文案
  当契约"。
- **脏数据/空值防御普遍缺位**：零价行情、null 字段渲染、storage 不可用——假定"数据总是干净的"。

## 二、本次迭代得失总结

### 得
- **投入产出高**：14 个缺陷修复集中在本轮几次提交，单个修复多为小改（≤20 行），却拦下
  **1 个隐私泄露**（邮箱明文上公开榜）、**1 个永久 500**（房间页）、**1 个并发死锁**。
- **把"查"沉淀成"自动化"**：点击爬虫（`click_crawler`）、PR 踩坑扫描器（`pr_guard`，调试中
  当场逮到 event.js 漏改）、知识库、回归用例——一次排查的成本摊到了后续每个 PR。
- **回归套件立即见效**：新增 6 个用例就逼出了一个上轮没修全的死锁（T-06），证明"补测试"
  不是形式主义。

### 失 / 代价
- **自引入回归**：13 个 bug 里 3 个是本轮前期脱敏改动造成的，等于"修 bug 的过程本身又埋了
  bug"——根因是改动影响面分析不足 + 测试滞后于声称。
- **启发式工具有误报成本**：`pr_guard` 初版全仓 59 处告警（多为噪声），花了几轮调参才降到 4 处；
  说明"规则要贴着代码库调"，上来就上硬门禁会被淹没。
- **环境坑消耗**：本地 mysqld 掉线、旧 JVM 配新 classes 假 500 等若干次（已记 `issue_recode/1.md`），
  属一次性环境摩擦，但提示本地验证环境不够稳定。

### 一句话
**本轮用小代价修掉了高危缺陷并建起了防复发的工具链；但近半缺陷是自引入回归，暴露"改动影响面
分析 + 测试先于声称"这两个流程缺口——这是下一步改进的靶心。**

## 三、长期质量改进行动计划

### 短期（1–2 周，立即可做）

| 行动 | 对应缺口 | 验收标准 |
|---|---|---|
| S1 **并发用例补全**：注册、零价行情 tick、限流清理三处补集成/单测（每日双开已补） | 并发系统性缺测 | 对应测试进 `mvn test`，4 条并发路径全有覆盖 |
| S2 **注册前缀保留字**：注册入口拒绝 `smoke_/btncheck_/shot_` 开头 | 测试前缀误伤真人（长尾风险） | 注册该前缀返 400；补单测 |
| S3 **pr_guard 接入 CI**：先 `--all` 非阻断跑起来，观察一周噪声再决定是否 `--strict` | CI 规则已配但未接 | CI 有 pr_guard 步骤，输出进 PR |
| S4 **前缀双源收敛**：`TEST_PREFIXES` 与 5 段 JPQL 收敛为单一来源（参数绑定或生成片段） | 前缀双源漂移 | 新增前缀只改一处 |
| S5 **RoomService 强结 catch 收窄**：区分"已结算"预期态与真故障，后者保留异常类型 | 异常吞掉掩盖真问题 | 真故障能被 M-5 告警区分 |

### 长期（1–2 个月，结构性）

| 行动 | 对应缺口 | 价值 |
|---|---|---|
| L1 **并发测试规范化**：建 `@Concurrent` 测试基类（CyclicBarrier + 线程池模板），所有"查-then-写/唯一键/状态迁移"接口默认要有并发用例 | 并发是最大盲区 | 并发 bug 测试左移 |
| L2 **可观测性补齐**：引入轻量 APM 或结构化日志 + 看板（Hikari 连接、5xx/path、LLM 配额、榜单空窗哨兵），替代现在纯 grep 关键字 | 无 APM，靠日志关键字 | 线上问题分钟级发现 |
| L3 **前端类型/契约校验**：无构建站引入轻量运行时契约校验（或迁 TS 子集），拦住"null 字段渲染/字段改名"类回归 | 前端无类型兜底 | 空值/契约 bug 编译期拦 |
| L4 **变更影响面清单化**：高风险改动（脱敏/口径/事务/并发）走"影响面 checklist"模板，强制列出受影响的判断点与需补的测试 | 自引入回归的根因 | 从流程上堵住"改一处坏一片" |
| L5 **DST/时区口径统一**：出海前把 `qsWeekIndex` 等时间计算统一为日历日差 | DST 周界偏移（长尾） | 多时区正确 |

## 四、团队开发规范增补条目

> 以下已部分固化进 `CLAUDE.md` 与 `docs/bug-knowledge-base.md`；此处汇总为"增补清单"，
> 供并入团队规范/PR 模板。

**改动影响面（新增，针对自引入回归）**
- [ ] 改动"展示数据/脱敏/口径/状态机"时，**全局搜受影响的判断点**（身份比对、过滤、数值计算），逐一确认。
- [ ] 高风险改动**在声称完成前先补回归测试**，不靠"看起来对了"收工。

**事务**
- [ ] 事务方法内 catch 另一事务方法的异常，确认内层是否已把物理事务标记 rollback-only；要隔离失败用 `REQUIRES_NEW`。
- [ ] `catch DataIntegrityViolation` 后不在同事务继续写（改 `INSERT IGNORE` 或直接抛业务异常收场）。
- [ ] `REQUIRES_NEW` 内的 `SELECT ... FOR UPDATE` 确认不与父事务持锁冲突；确定性内容别用 FOR UPDATE 回读。

**分页 / 查询**
- [ ] 过滤必须在 SQL/JPQL 层、分页之前；禁止对分页结果再 `.filter()`。
- [ ] 同一过滤口径避免散落多处（常量 + 多段 SQL）。

**并发**
- [ ] "查-then-写"对唯一键做并发保护；"查-then-写/状态迁移/唯一键"接口默认配并发用例。

**空值 / 边界**
- [ ] `BigDecimal.divide` 带 scale+RoundingMode；除数来自数据先判 `signum()`。
- [ ] 前端渲染后端数值字段 `v == null ? "--" : fmt(v)`；脱敏/截断函数覆盖"输入短于保留长度"。
- [ ] 依赖 `localStorage` 的稳定标识有内存兜底 + try/catch。

**状态判断 / 异常**
- [ ] 不用错误文案子串做分支，用状态码/异常类型。
- [ ] "每日/每局一次"标记在动作**开始**时落（防跨零点/刷新）。
- [ ] 视图依赖 `qs:view` 加载的有"刷新直达"启动兜底。

**自动化门禁（已建，纳入流程）**
- [ ] 后端改动过 `mvn test`(84)；前端改动过 `ui_check` + `npm run buttons`（+ 必要时 `crawl`/`smoke`）。
- [ ] PR 评审参考 `pr_guard.py` 告警逐条确认。
- [ ] CLI 脚本遇问题记 `issue_recode/`；通过即 commit，不留未提交改动。

---

**复盘结论**：本轮缺陷以编码疏漏为主（57%）、架构隐患次之（36%），而**最该改的不是某类 bug 本身，
而是"改动影响面分析 + 测试先于声称 + 并发路径必测"这三个流程缺口**——短期 S1/S3、长期 L1/L4
直接对准它们。工具链（爬虫/扫描器/知识库/回归套件）已把"排查"变"自动拦截"，后续迭代的同类
bug 预期可在 PR 阶段被挡下。
