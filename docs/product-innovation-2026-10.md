# QuantSim 模拟炒股游戏产品创新优化全方案

> 2026-10。基于当前代码库现状推演：已有经典对局、好友房间、每日挑战、每日一猜、名场面事件局、
> 藏品档案馆（声望+历史藏品，从进度派生）、学堂（章节+词典）、回测工坊（含调参/策略对决 duel）、
> 重生逆袭、大富翁、泡沫局、抄底局、期权挑战、生涯模式、桌宠、积分商店。
> 后端：Spring Boot 3 + Flyway + Caffeine，BlindDates 竞技脱敏，进程内 RateLimiter，LLM 顾问（日配额硬顶）。
> 本文每条玩法都给出"规则细节 + 复用哪些现有设施 + 新增成本评级（S小/M中/L大）"。

## 一、核心玩法创新方案（对局模式 + 行情机制）

### 1.1 多模式对局矩阵

现状：经典对局（60 tick 手动推进）、每日挑战（全服同窗口盲局）、好友房间（同窗口异步比）。
在 `GameSession` 上加 `modeRules` JSON 列（Flyway 新迁移），开局时由"模式模板"注入，结算按模板计分——
不动结算主流程，只扩规则参数。

| 模式 | 规则细节 | 复用 | 成本 |
|---|---|---|---|
| **极速赛（10 分钟）** | 服务端定时自动 tick（每 8 秒推 1 根 K 线，75 根≈10 分钟），玩家只做买卖/挂单决策；超时未操作视为持仓不动。进行中页面倒计时+音效压迫感 | tick 逻辑已存在，补 `@Scheduled` 批量推进器 + SSE 推送（advisor 已有 SSE 先例） | M |
| **赛季长线赛** | 一个赛季 = 真实 4 周；每天只放 3 根 K 线额度（防刷完就走），赛季末按累计收益+回撤的复合分结榜。断签不惩罚、补签消耗积分（接现有积分商店） | 每日挑战的"全服同窗口"+ BlindDates；`user_points` 已有 | M |
| **天梯淘汰赛** | 周末定时开赛：128 人报名，每轮 15 分钟极速局，收益后 50% 淘汰，7 轮决出冠军。轮间 5 分钟休息展示上轮战报 | 极速赛做完后，加 `tournament` 表 + 轮次状态机 | L |
| **1v1 单挑** | 双方同一盲窗口、同规则池，先手方选"规则卡"后手方选"标的池"（双盲互选制造博弈）；结算并排复盘 | duel.js 已有策略对决骨架，房间 2 人上限即是 1v1 | S-M |
| **组队联赛** | 3 人队，队伍成绩 = 中位数收益（防一人带飞/摆烂），赛程循环积分 | 依赖俱乐部系统（见模块五），排后 | L |

**防刷原则**（延续教训 #5）：所有竞技模式手动成交只按收盘价、其他价位走次日挂单撮合；极速赛自动 tick 下
挂单在下一根 K 线按 OHLC 撮合，规则与现有完全同口径（`FeeCalculator` 复用）。

### 1.2 动态扰动行情（告别纯复刻）

现有行情是真实/mock 历史回放。加一层**扰动引擎**（新 `service/MarketPerturbation`），在 BlindDates 脱敏后的
K 线序列上做确定性变换（以 sessionId 为随机种子，同局玩家看到同一扰动，可复现、可复盘）：

- **新闻冲击**：开局注入 2-4 条虚构新闻事件（已有 news 事件管线），生效日对 OHLC 乘冲击系数（利好 +3%~+8%，利空对称）；新闻提前 1-2 天"预告"（市场传闻），考验玩家信还是不信——传闻 30% 概率不兑现。
- **流动性冲击**：随机 3-5 天标记"缩量日"，当日挂单成交量上限 = 持仓的 30%（撮合时截断），大仓位玩家被迫分批离场。
- **停牌**：5% 概率触发 2-3 天停牌（K 线空窗，持仓冻结），复牌首日波动放大 2 倍。做多做空都要留流动性余量。
- **黑天鹅**：每局 ≤1 次、概率 8%，单日 -15%~-25% 跳空；但掉落补偿——黑天鹅局存活（结算为正）掉限定藏品（见模块二）。

实现要点：扰动只改**下发给前端和撮合引擎的序列**，不碰 `daily_price` 原始数据（行情只读纪律）；
扰动参数入 `modeRules`，结算复盘时全部揭晓（"本局扰动清单"）。成本 M。
竞技局新闻文本必须用虚构模板库，不用真实新闻（教训 #4：文本会暴露真实时间）。

### 1.3 对局规则池（每局变阵）

规则卡池（开局随机 2 张或房主自选），全部是**约束类**而非增益类（约束改变博弈、增益破坏公平）：

| 规则卡 | 效果 | 实现点 |
|---|---|---|
| 满仓禁令 | 单标的仓位 ≤70% | trade 校验加一行 |
| 做空解禁 | 允许融券（利息 0.05%/日） | 持仓支持负数 + FeeCalculator 加息费口径 |
| 行业禁买 | 随机 1 个行业不可买入 | stocks 已有行业字段 |
| T+0 特权 | 当日买当日卖（但手续费 ×2） | 解除 T+1 校验 + 费率参数 |
| 杠杆 1.5x | 可融资至 1.5 倍（强平线 110%） | 账户加负债字段，tick 时查强平 |
| 止损强制 | 单笔浮亏 -8% 自动平仓 | tick 钩子 |

实现：规则全部收敛进 `modeRules` JSON + 一个 `RuleEnforcer`（trade/tick 两个切入点），枚举白名单解析
（延续 `Enums.parse` 纪律）。成本 M（做空与杠杆单独 L，建议 P1 后半）。

### 1.4 观战与复盘

- **延迟观战**：房间对局进行中，可看对手"3 个 tick 之前"的持仓快照与净值曲线（防实时抄作业）；
  数据从 `game_session` 派生，加 Caffeine 短缓存即可。标的继续匿名（BlindDates 口径不变）。成本 S-M。
- **自动复盘报告**：结算时已有 `GameBenchmarks` 复盘纯计算，扩展为：买卖点标注 K 线图、
  择时得分（买在局部低点的比例）、持仓集中度、换手率、vs 满仓躺平/vs AI 的差距分解；
  行为画像接现有 `BiasAnalysisService`（追涨/割肉/处置效应已在算）。成本 S（大半已有）。
- **经典对局回放**：复盘页加"逐 tick 回放"（前端用已存的 K 线+交易流水重演，零后端改动）。成本 S。

## 二、成长 & 藏品成就体系

### 2.1 交易风格身份

`BiasAnalysisService` 已输出行为指标，在其上加风格判定（纯派生，零新表，延续 relics.js "从进度派生"的
优秀设计）：

- **趋势猎手**：>60% 买入发生在 MA5>MA20 时；**价值潜伏**：平均持仓 >15 tick 且低换手；
  **短线游击**：换手率 top 分位 + 平均持仓 <4 tick；**套利工匠**：挂单成交占比 >50%。
- 近 20 局滚动判定，主身份 + 副身份；身份页展示雷达图（ECharts 已有）。
- 身份解锁专属：头像框（CSS 渐变，复用藏品配图线性图形体系）、结算报告专属评语模板、
  对局内**分析工具皮肤**（不是数值增益）。

成本 S-M。注意：判定规则公开（学堂可查），引导玩家刻意练习不同风格——本身就是教学。

### 2.2 藏品获取与稀有度

现有：名场面通关掉历史藏品 + 声望。扩展为四稀有度 + 多掉落源：

- **普通**（学堂章节通关）/ **稀有**（每日挑战周榜 top10%、黑天鹅存活）/
  **史诗**（天梯 8 强、赛季 top50、特殊挑战如"全程零割肉获胜"）/
  **传说**（赛季冠军、名场面全成就、策略擂台月冠军，全服限量编号 #001-#100）。
- **弱被动增益红线**：只允许"信息类"增益（如：带某藏品可在复盘报告多看一项指标、开局多看 5 根历史 K 线），
  **禁止任何影响成交/收益的数值增益**——竞技公平是本产品命根（审计教训全在防不公平）。
- 掉落用确定性规则而非概率（达成即得），概率掉落放宽到"保底 + 可见进度条"（如黑天鹅存活 3 次必得），
  避免赌博感（合规考虑）。

实现：`relic_catalog`（目录）+ `user_relic`（获得记录，含限量编号）两张新表（Flyway），掉落判定挂在
各结算点（对局结算/赛季结算/学堂通关均已有事务入口）。成本 M。

### 2.3 交易履历博物馆

- 自动"封存"满足条件的对局：收益 top3 个人纪录、黑天鹅局、首次各模式通关、天梯决赛——
  存 `session_archive`（sessionId + 封存理由 + 快照 JSON），复盘页永久可回放。
- 个人史册页：时间轴（首局/首胜/首个史诗藏品/巅峰一战），一键生成分享卡
  （sharecard.js 已有分享卡管线，直接扩模板）。成本 S-M。

## 三、学堂模块游戏化重构

### 3.1 知识技能树

现有学堂是章节阅读。重构为 5 条分支技能树（K 线/基本面/宏观/风控/量化），每节点 = 1 个概念：

- 节点状态：锁定 → 可学（读图文，复用现有章节内容拆分）→ **试炼**（见 3.2）→ 点亮。
- 点亮给技能点；技能点解锁**对局分析工具**：MACD/RSI 面板（app.js 已有指标开关，改为需解锁）、
  复盘报告高级指标、行业热力图（heatmap.js 已有）视角。关键设计：工具提供**信息**不提供收益，
  新手没工具也能玩，老玩家工具全开——成长感不破坏公平。
- 前端技能树用 SVG 连线 + 现有卡片样式；进度存现有用户进度表模式。成本 M。

### 3.2 知识试炼（微缩模拟局）

每个节点的试炼 = 一个 **5-10 根 K 线的微缩对局**，带判定条件：

- 例："金叉" 节点：给 8 根 K 线，要求在金叉出现的 ±1 tick 内买入且盈利离场；
- 例："止损" 节点：行情必跌（扰动引擎注入），达标条件是亏损 ≤5% 离场（教会认错）；
- 例："仓位管理"：3 只标的，要求单标的 ≤50% 且总收益为正。

实现：微缩局就是 `modeRules` 的一个极端模板（totalTicks=8，判定条件入规则 JSON），完全复用对局引擎，
**学=玩同一套系统**。出题数据用 mock 生成器（mock_data.py 已可按种子造任意形态，加形态注入参数）。成本 M。

### 3.3 导师系统

- 高声望玩家（声望 ≥ 阈值）可把自己某场封存对局发布为"挑战帖"：同窗口同规则，擂主成绩为及格线；
- 挑战者超越擂主，双方都得声望（擂主被打败也得——鼓励发高质量题）；
- 复用：房间的"同窗口比成绩"机制 + 博物馆封存数据，新增 `challenge_post` 一张表。成本 M。
- 防刷：发布限频（RateLimiter 现成）、挑战同一帖计分一次。

## 四、量化策略沙盒

### 4.1 策略编辑器（拖拽 + 规则式，不做 Python）

现有 `BacktestEngine` 的自定义策略 = enum 白名单字段/算子组合，**这就是拖拽编辑器的后端**。
前端把现有表单升级为"条件积木"：IF [MA5] [上穿] [MA20] AND [RSI] [<] [70] THEN [买入] [30%仓]。

- **明确不做 Python 子集**：eval/沙盒逃逸风险与现有"零 eval 纪律"冲突（审计红线），且 JVM 内嵌
  Python 解释器成本 L+。规则式积木已覆盖 90% 教学价值；真要扩表达力，加字段和算子枚举即可（成本可控、天然安全）。
- 积木数上限 8 个条件（防策略过拟合也防 UI 失控）。成本 M（后端 S，前端 M）。

### 4.2 策略擂台

- 玩家提交策略（参数 JSON 入库），每晚定时在"明日新开的盲窗口"上全量跑一遍（批量回测，
  `BacktestTuner` 的网格执行器改成策略清单执行器），按周滚动收益排名；
- 关键公平设计：**在未来数据上比**（每晚新窗口），杜绝对历史过拟合刷榜——这是和一般回测榜的本质差异；
- 限流：每人同时在榜策略 ≤3 个，提交/替换每日 ≤5 次（防撞参数矩阵，RateLimiter 现成）。
- 压力点：策略数 × 窗口长度的批量回测要压测（见模块六）。成本 M-L。

### 4.3 策略开源广场

- 发布策略 = 公开参数 JSON + 作者说明；他人"复刻"产生 fork 关系（`parent_strategy_id`），
  微调后再发布形成版本链；页面展示 fork 树与各版本擂台成绩对比；
- 原作者激励：被 fork 的策略上榜，原作者得 10% 声望分成（链路只溯源一层，防传销式分成）；
- 版本管理就是"不可变记录 + parent 指针"，无需真 git。成本 M。

## 五、社交、赛季叙事与经济循环

### 5.1 赛季世界观

- 赛季 = 8 周，每季一个主题，直接复用**名场面事件库**做叙事骨架（如 S1"泡沫纪元"：主线任务串
  泡沫局/2000 科网/2015 杠杆牛三个现有玩法；S2"危机编年史"串 2008/熔断/黑天鹅扰动局）；
- 主线任务 = 既有玩法的定制目标清单（打 X 场极速赛、黑天鹅存活 1 次、技能树点亮风控分支……），
  季末按完成度给赛季限定藏品 + 称号；
- 赛季榜结算后**归档**（`season_archive`，历史赛季榜单永久可查——榜单荣誉是核心资产）。
- 成本 M（内容工作量为主，系统是任务清单 + 归档表）。

### 5.2 俱乐部

- ≤20 人，周贡献 = 成员各模式积分加权和；俱乐部榜 + 专属挑战（全员本周合计完成 N 场每日挑战
  → 全员掉稀有藏品）；
- 复用房间的成员模型（room/room_member 结构直接参考），新增 club/club_member 两张表；
- 并发写入走 `findWithLockBy` 悲观锁纪律（加入/退出/贡献结算）。成本 M-L（含 UI 两个新视图）。

### 5.3 游戏内经济

现有：积分（user_points，商店消耗）+ 声望（纯派生，不可消耗）。扩展为三轨：

- **模拟币**：对局入场/奖励用（极速赛门票 100，冠军 500……），产出端全部来自对局表现，
  消耗端：补签卡、规则卡自选权、俱乐部创建费、分享卡高级模板；
- **声望**：永不消耗、只增不减，决定导师资格/限量藏品优先购——是"段位"不是"货币"；
- **藏品交易市场（谨慎设计）**：只允许**普通/稀有**档在市场挂牌（史诗/传说绑定灵魂，保住荣誉价值），
  模拟币计价，交易双向收 10% 手续费（主要回收水龙头）；每周挂牌限 3 件（防工作室）。
- **防通胀三件套**：①所有产出有日上限（RateLimiter.checkDaily 现成）；②手续费+门票是持续回收口；
  ③每月监控 M2（模拟币总量）仪表盘，产出系数可配置热调（`quantsim.economy.*` 配置项）。
- 成本：模拟币 M；交易市场 L（撮合+防刷+客服争议，建议 P2 再评估是否真的要做）。

## 六、落地优先级评估 & 技术风险清单

### 6.1 反作弊

| 风险 | 对策 | 复用 |
|---|---|---|
| 多账号互喂（1v1/导师挑战小号送分） | 同 IP 对局降权计分；新号（<5 局）成绩不入公开榜 | RateLimiter 的 IP 维度现成 |
| 高频刷极速赛拿保底掉落 | 掉落日上限 + 收益为负的局不计掉落进度 | checkDaily 现成 |
| 策略擂台撞参数 | 提交限频 + 未来数据评测（4.2 已内置） | — |
| 观战信息泄露 | 延迟 3 tick + 标的匿名不动摇 | BlindDates |
| 脚本代打极速赛 | 操作间隔熵检测（全是整秒间隔报警），先只标记人工审 | 新增，S |

### 6.2 性能压力点

- **极速赛自动 tick**：100 并发局 × 8 秒/tick = 12.5 tick/秒，每 tick 含撮合+写库——撮合逻辑轻，
  瓶颈在逐局行锁写 `game_session`；对策：极速局状态内存化（Caffeine）+ 每 5 tick 批量落库，结算时强一致。
- **策略擂台夜批**：1000 策略 × 480 根 K 线回测，按现有 BacktestEngine 单策略 <100ms 估算约 2 分钟，
  可接受；上 1 万策略需分片，先设策略总量上限。
- **榜单**：赛季榜/俱乐部榜必须预聚合（定时物化成绩表），别实时聚合——现有榜单已踩过分页过滤的坑（知识库 #1）。
- **限流是进程内的**：天梯/极速赛多实例部署前必须换 Redis（CLAUDE.md 既有 TODO，这些玩法会放大它）。

### 6.3 分阶段优先级

- **P0（2-4 周，纯复用+小增量）**：1v1 单挑（S-M）、复盘报告增强+逐 tick 回放（S）、交易风格身份（S-M）、
  藏品稀有度分层+黑天鹅扰动（M）、履历博物馆+分享卡（S-M）。
- **P1（1-2 月）**：极速赛+自动 tick（M）、规则卡池第一批（禁买/仓位/止损，不含做空杠杆）（M）、
  技能树+微缩试炼（M）、策略积木编辑器+擂台（M-L）、赛季任务+归档（M）。
- **P2（远期，逐项再评估）**：天梯淘汰赛（L）、做空/杠杆规则卡（L）、组队联赛+俱乐部（L）、
  藏品交易市场（L，含合规评估）、导师系统（M，依赖声望体系成熟）。

### 6.4 风险提示

- **最容易破坏平衡**：藏品数值增益（已用红线禁止）、做空+杠杆组合（爆仓体验差+撮合复杂度平方级）、
  藏品市场（通胀+工作室，P2 再议）。
- **开发成本最高**：Python 策略沙盒（已否决，用积木替代）、实时多人同屏对战（现有异步比成绩模式
  已够竞技感，别上 WebSocket 实时同步的当）、天梯赛事状态机（断线/弃赛/并列的边角案例极多）。
- **合规**：全程虚拟货币、不可提现、掉落保底可见——避免赌博定性；藏品市场若做，仅限游戏内且禁止场外交易声明。
