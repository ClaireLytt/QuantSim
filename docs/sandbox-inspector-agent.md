# QuantSim 持续仿真巡检 Agent 设计文档

> 一个长期运行的"数字沙盘"：持续生成混合用户行为流（正常/边缘/恶意），追踪全部业务实体状态，
> **自动校验业务不变量**，一旦违反即输出事件时序回放 + 根因 + 可复现用例 + 修复建议。
> 支持两种模式：**(a) 推演模式**（纯逻辑沙盘，`tools/sim/montecarlo_sim.py`，无需真实服务）与
> **(b) 测试对接模式**（打测试环境真实接口做混沌巡检）。末尾附**可复用巡检提示词**。

---

## 一、Agent 工作流程

```
┌─ 加载知识库 (历史 bug / 状态机 / 接口 / 业务规则 / 权限 / 攻击链)
│
├─ 1. 生成混合行为流
│     ├ 正常操作 (按昼夜概率模型)
│     ├ 边缘操作 (刷新/中途退出/跨零点/弱网中断)
│     └ 恶意尝试 (并发双开/快速连点/刷分循环/越权猜测)
│
├─ 2. 驱动事件流 (推演模式=DES 引擎; 对接模式=真实 HTTP)
│     └ 追踪实体状态: 对局/房间/每日一猜/榜单/藏品/任务奖励/结算记录/点数
│
├─ 3. 持续校验不变量 (每事件 / 周期末)
│     └ 命中违反 → 记录 {时序回放, 分类, 风险级, 根因, 复现用例, 修复建议}
│
├─ 4. 周期末汇总 → 沙盘巡检报告 (违规清单 + 事件统计 + 高冲突窗口)
│
└─ 5. 告警分级推送 (P0 立即 / P1-P3 汇总); 回灌知识库 (新发现→新不变量/新攻击原型)
```

**循环**：每个仿真周期（如推演 72h / 对接模式 N 分钟）结束出报告，可重复调用持续跑。

## 二、不变量校验清单（业务恒成立规则）

> 每条给：不变量、校验方式、违反风险级。推演模式在 `montecarlo_sim.py` 的不变量层实现。

| ID | 不变量 | 校验方式 | 违反级 |
|---|---|---|---|
| **INV-NO-500** | 任何操作不得产生 5xx（除零/事务/幂等守卫全程有效） | `err_500 == 0` | P0 |
| **INV-NO-DEADLOCK** | 锁序设计不成环 | `deadlock == 0`（或容忍阈内） | P0 |
| **INV-ROOM-CONVERGE** | 房间到期强结必收敛 SETTLED，不污染父事务 | `force_settle == settled` 且无 `UnexpectedRollbackException` | P0 |
| **INV-STATE-LEGAL** | 对局状态只 `IN_PROGRESS→SETTLED`（单向终态） | 跟踪转移，断言无非法跳转/SETTLED→IN_PROGRESS | P0 |
| **INV-REWARD-IDEMPOTENT** | 奖励不可重复领：每日挑战每人每天一局、签到/任务位每日一次 | `uk_user_daily` + taskFlag；并发双开必被 400 挡 | P1 |
| **INV-ECON-BOUNDED** | 单用户得分速率被动作成本自然限制（无限刷分侦测） | 单用户结算次数 ≤ 正常上限；否则标记 farmer（**逮 SEC-1**） | P0 |
| **INV-ECON-NEG-EV** | "消耗得收益"类必须负 EV（盲盒成本 ≥ 期望收益） | 静态核：redeem 成本 ≥ E[win]（**逮 SEC-2**） | P0 |
| **INV-BOARD-FILTER** | 公开榜 TOP N 不含测试账号、邮箱已脱敏、过滤在分页前 | 榜单快照断言无 `smoke_/btncheck_/shot_`、无 `@` 未脱敏 | P1 |
| **INV-IDENTITY** | 脱敏与身份判断一致：脱敏后仍能用 `isSelf` 认出本人 | 本人上榜断言 `isSelf=true`，他人 `false` | P1 |
| **INV-NO-DIVZERO** | 数学计算不除零（零价行情） | 零价守卫命中计数，确认全被接住无 500 | P1 |
| **INV-AUTHZ** | 按 ID 操作只能本人；受保护接口游客 401 | 越权猜测他人 sessionId → 必 404；游客打受保护 → 401 | P0 |
| **INV-DAILY-CLOCK** | 每日限次用服务端日界，客户端改钟不可绕过服务端奖励 | 改钟注入 → 服务端 taskFlag/uk 不受影响 | P1 |

## 三、用户行为概率模型

**昼夜权重**（24 桶）：0-6 低谷 0.1~0.2，9-11/19-22 高峰 0.9~1.0；发起间隔 ∝ 1/权重。

**用户原型分布**（500 用户）：
- **普通用户（~95%）**：按操作混合权重随机——leaderboard 28 / trade 20 / room_view 10 / daily_guess 8 /
  game_start 8 / settle·daily_start 6 / register·undo 2。
- **边缘用户行为（混入）**：double_settle 3（连点结算）/ slow_trade 3（长持锁）/ double_daily 2（双标签页）/
  refresh_room 2（刷新重复）。
- **恶意刷分者（~3%, N_FARMERS=15）**：紧密 `start→settle` 循环（1~4s/轮），模拟 SEC-1 攻击链。
- **跨零点注入**：零点 ±2min 的每日一猜/挑战，20% 概率触发时钟边界事件。
- **行情零价注入**：trade 时 0.3% 概率命中零价（验证除零守卫）。

**房间生成**：每 30min 批量 3~10 房（各 2~8 人，TTL 30min）→ 制造集中到期突发（X1 触发条件）。

## 四、异常输出格式（命中违反时）

```
[违反 INV-XXX] 风险级: P0/P1/P2
├ 时序回放: t=.. 用户 uX 操作A → t=.. 操作B (并发 uY 操作C) → 违反点
├ 问题分类: 事务/并发/状态/经济/越权/渲染
├ 根因推测: <基于知识库的根因假设>
├ 可复现用例: <集成测试/curl 脚本骨架>
└ 修复建议: <对应 HANDBOOK 规则 + 具体改法>
```

## 五、沙盘巡检报告模板

```markdown
# 沙盘巡检报告 · <周期> · seed=<n>
## 规模
总操作 N / 用户 U / 仿真时长 H / 连接池 P
## 不变量结果
INV-NO-500: PASS/FAIL  ...  (逐条)
整体: invariant_pass = true/false
## 违规清单 (按风险级)
- [P0] INV-ECON-SEC1: <detail> → 时序/根因/用例/建议
## 事件统计
业务拒绝(400) 分项 / 房间强结成败 / 零价守卫 / 跨午夜 / 死锁 / 连接超时 / 池峰值
## 高冲突窗口
锁等待 Top5 小时 / 连接超时窗口
## 结论与跟进
```

## 六、告警规则（分级，防风暴）

| 级 | 触发 | 动作 |
|---|---|---|
| **P0** | INV-NO-500 / NO-DEADLOCK / ROOM-CONVERGE / ECON / AUTHZ 任一 FAIL | 立即输出违规 + 呼叫 |
| **P1** | REWARD-IDEMPOTENT / BOARD-FILTER / IDENTITY / NO-DIVZERO / DAILY-CLOCK FAIL | 周期报告高亮 + 1h 内跟进 |
| **P2** | ROOM-CONSISTENT（设计内部分成员未结算）/ 慢窗口异常 | 报告记录 + 趋势观察 |
| **P3** | 行为统计异常（如某 farmer 识别）但未违反硬不变量 | 趋势观察 |
- 同类违规周期内去重；P2/P3 进报告不即时呼叫。

## 七、两种模式

### (a) 推演模式（默认，纯逻辑沙盘）
`python tools/sim/montecarlo_sim.py [seed]`——生成器驱动 DES，忠实复刻锁序/连接池/房间强结/唯一键语义，
内置不变量层，无需真实服务。**用途**：回归验证、锁序/死锁推演、经济漏洞侦测、CI 可复现。

### (b) 测试对接模式（真实接口混沌巡检）
对接测试环境（`QUANTSIM_URL`），用真实 HTTP 打接口：
- 行为流映射到 API：`POST /game/start`→`/settle`、`/daily/start`、`/me/points/*`、`/rooms/*`、`/leaderboard`。
- 不变量校验改为**接口响应 + DB 快照断言**：榜单返回无测试账号、重复 settle 返 400、并发双开 1 成 N 败、
  越权他人 sessionId 返 404、积分发放是否超速。
- 复用现有 `tools/ui_smoke/`（Playwright）做前端链路，`tools/pr_guard.py` 做静态巡检。
- **安全**：用 `smoke_` 前缀账号（榜单自动隔离）、回测走 `preview`、不打生产。

## 八、可复用沙盘巡检提示词（可重复调用）

> 复制下文作为 Agent 调用提示，可反复跑持续巡检。

```
你是 QuantSim 持续仿真巡检 Agent。知识库 = docs/HANDBOOK.md + docs/bug-knowledge-base.md +
docs/security-audit-business.md + docs/fault-tree-analysis.md。

本轮任务:
1. 推演模式: 运行 python tools/sim/montecarlo_sim.py <seed>, 读取 JSON 输出的 violations 与统计。
   (可改 seed 多轮, 或改 N_FARMERS/行为权重做对抗性加压。)
2. 对每条 violation: 输出时序回放 + 问题分类 + 根因推测 + 可复现用例 + 修复建议 (对应 HANDBOOK 规则)。
3. 校验本文档第二节全部不变量; 任一 P0/P1 FAIL 即详述, 全 PASS 则给"本轮无违规"结论。
4. 按第五节模板出沙盘巡检报告; 按第六节分级告警。
5. 若发现知识库未覆盖的新异常模式: 提议新增一条不变量 + 一条 pr_guard 规则 + 一条回归用例。

约束: 不改生产; 测试账号用 smoke_ 前缀; 报告数字必须来自真实仿真输出, 不得编造;
发现的 P0 经济漏洞 (如 SEC-1/SEC-2) 若已在知识库登记则标注"已知", 新发现才算新违规。
```

## 九、实测验证（沙盘逮到真漏洞）

一次推演（seed=20261015，12h，混入 15 个刷分攻击者原型）的**真实输出**：

```
ops=146,884  invariant_pass=False  pool_peak=7/20
INV-NO-500   PASS (err500=0)      INV-NO-DEADLOCK PASS (deadlock=0)
INV-ROOM-CONVERGE PASS (强结135=收敛135)   连接超时=0  零价守卫64 全接住
业务拒绝正确: daily双开 10,605 / 注册dup 898 / 已结算重复 3,093 全转 400

[P0] INV-ECON-SEC1 违反: 438 个用户结算次数超正常上限(15);
     最高用户 u13 结算 2488 次 = 124,400 积分 (无每日上限, 可无限刷)
```

**解读**：被修复的不变量（无 500 / 无死锁 / 房间收敛 / 幂等 400 / 除零守卫）**全部 PASS**，验证本轮修复稳定；
而**经济不变量 `INV-ECON-SEC1` 被触发**——沙盘用业务断言**自动复现并量化了安全审计的 SEC-1**（单账号
12h 刷 12.4 万积分）。这正是本 Agent 的价值：把"应当恒成立的规则"变成可自动证伪的断言，跑一轮即大规模
证伪，新/已知漏洞都无处藏。

---

**设计要点**：这个 Agent 的价值不在"跑流量"，而在**用业务不变量把"系统应当恒成立的规则"固化成可自动
证伪的断言**——沙盘每跑一轮就是对这些不变量的一次大规模证伪尝试。推演模式零成本可复现（CI 可跑），
对接模式验证真实接口。新发现回灌知识库形成闭环：异常 → 新不变量 → pr_guard 规则 → 回归用例。
