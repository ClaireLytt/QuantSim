# QuantSim 用户体验精细化优化报告（2026-10）

> 范围：只做体验层优化、流失分析、交互打磨，**不新增大型玩法**。所有方案以现有前端为基线（无构建 IIFE + i18n 双语 + 单一 toast + glossary 词典 + 一次性 onboarding），每条标注"现状 → 优化 → 落点文件"。
> 现状盘点依据：`toast()` 单样式 3 秒无分级（app.js:162）；onboarding 为一次性布尔旗（app.js:3061）；`glossary.js` 术语体系已存在（251 处 term 引用，linkifyTerms 已做转义）；**全站无任何埋点**；媒体查询仅 19 处；交易页快捷键缺失。

## 1. 用户全链路旅程与流失节点分析

### 1.1 旅程图（九站）

```
首页进入 → 游客试玩/注册 → 新手引导 → 首次对局 → 对局中(5~20天推进)
 → 结算复盘 → 学堂/研究所深潜 → 竞技循环(每日挑战/房间/赛季) → 长期留存 or 流失
```

### 1.2 分站流失风险清单（P0=直接劝退 / P1=显著折损 / P2=体验毛刺）

| # | 站点 | 流失触点 | 心理机制 | 级别 |
|---|---|---|---|---|
| J1 | 首页 | 首屏信息过载：榜单+任务+签到+积分+宠物同屏，新用户不知道"第一步点哪" | 选择过载 → 放弃 | **P0** |
| J2 | 游客进入 | 游客可玩是优势，但"游客记录会丢吗"无说明，玩了一局怕白玩 | 损失厌恶未被安抚 | P1 |
| J3 | 新手引导 | 一次性引导讲完即忘；错过（误点关闭）后无法重看 | 认知超载 + 不可逆 | **P0** |
| J4 | 首次对局 | 开局参数（市场/行业/AI 难度/真实规则）全暴露，新手不懂先选什么；第一天亏钱即想关页 | 决策瘫痪 + 首败挫折 | **P0** |
| J5 | 对局中 | "下一天"循环的中段（第 8~15 天）单调；满仓躺平无事可做 | 心流断裂 | P1 |
| J6 | 结算复盘 | 复盘信息量大（基准对比/风险指标/偏差诊断/AI 日志），赢了只想看"赢多少"，输了只看到一堆红字 | 反馈与情绪不匹配 | P1 |
| J7 | 学堂 | 从对局到学堂无情境桥：输在"追涨"却要自己去学堂里找对应课程 | 动机-内容断链 | P1 |
| J8 | 竞技循环 | 每日挑战一天一次，打完没有"明天再来"的钩子；房间需要拉到真人 | 回访理由不足 | P1 |
| J9 | 长期 | 高阶玩家打穿 HELL AI 后无新目标；榜单被先行者占住 | 天花板 + 马太效应 | P2 |

### 1.3 三类人群的流失诱因与干预

**新手（0~3 局）—— 死于"看不懂 + 第一局就输"**
- 干预 1（J4）：**新手默认局**——开局卡默认折叠高级参数（市场/真实规则/AI 难度收进"高级设置"），一键"开始第一局"用 EASY + A股 + 休闲规则。落点：index.html 开局卡 + app.js。
- 干预 2（J4）：**首败安抚**——首局结算若为负收益，结算弹窗首屏不是红字收益率，而是"击败了 X% 的买入持有基准/你的第 1 局，输给 AI 很正常，看看它做对了什么 →（跳 AI 操盘日志）"。落点：结算弹窗文案分支。
- 干预 3（J3）：引导改情境式（见 §4），且头部加"❓重看引导"常驻入口。

**中期玩家（4~30 局）—— 死于"重复感"**
- 干预 4（J5）：对局中段注入微目标：状态栏加一行"本局小目标"（如：收益超过定投基准 / 一次止损挽回 ≥2%），结算时结算它。纯文案+判定，无新系统。
- 干预 5（J6）：复盘页"一句话诊断"置顶（已有偏差诊断数据，取触发率最高的一项生成），其余折叠。
- 干预 6（J7）：**败因→课程桥**：复盘诊断出"追涨"时，诊断卡尾部给"学堂 · 追涨杀跌 3 分钟课"直链。落点：复盘渲染 + academy 锚点。

**高阶玩家（30+ 局 / 打穿 HELL）—— 死于"没有对手"**
- 干预 7（J9）：突出**同题挑战**（已有 createChallenge）：结算页"就这局开房间约战"按钮从次要位提到主操作区——高阶玩家的对手是人不是 AI。
- 干预 8（J9）：榜单马太：主榜旁加"本周新面孔"切换 tab（只按本周开局的会话排），复用现有查询加时间条件。
- 干预 9：限制条件玩法（限笔数/交易理由）在高阶局推荐位展示——自我设限是高手的玩具（系统已有，只缺曝光）。

## 2. 页面信息架构与 UI 密度优化方案

### 2.1 各页信息优先级重排（核心操作 / 次要信息 / 辅助数据）

| 页面 | 核心操作（首屏必见） | 次要（折叠/下移） | 辅助（进入二级） |
|---|---|---|---|
| 首页 | "继续上局 / 开新局"单一主 CTA | 每日挑战入口、签到 | 榜单全量、任务列表、宠物 |
| 房间大厅 | 房间码输入 + 创建按钮 | 我的房间列表 | 规则说明 |
| 对局交易页 | K 线 + 买/卖/下一天 三键 | 挂单、AI 动向、持仓明细 | 新闻、顾问、指标开关 |
| 结算复盘 | 收益率 + 一句话诊断 + 两个去向（再来一局/约战） | 基准对比图 | 风险指标表、AI 日志、偏差明细 |
| 学堂 | 继续上次课程 | 课程目录 | 成就/进度统计 |
| 藏品档案馆 | 新获得/可解锁藏品 | 全收藏网格 | 掉落说明 |
| 个人主页 | 生涯胜率/段位一行概览 | 历史对局列表 | 回测历史、偏差档案 |

**落地规则**：每页首屏只允许 1 个主色按钮（主 CTA）；次要信息用 `<details>` 或 tab 折叠，不删功能只降噪。

### 2.2 全局密度规范（写进 design.md，统一执行）

现状问题：组件偏大、卡片内边距不一、信息密度低导致单屏可见内容少。

```
间距阶梯: 4 / 8 / 12 / 16 / 24px (--sp-1..5), 卡片内边距统一 --sp-4(16px), 卡片间距 --sp-3(12px)
字号阶梯: 12(辅助) / 13(正文表格) / 14(正文) / 16(卡片标题) / 20(页标题) / 28(大数字)
行高: 数据表 1.4, 文案 1.6
数字一律 font-variant-numeric: tabular-nums (榜单/资产列不跳动)
按钮高度: 主 36px / 次 32px / 行内 28px, 最小点击区 44×44 (触屏, 用 padding 补)
```
落点：style.css `:root` 加 `--sp-*` 变量，各域 css 渐进替换硬编码间距（每次只改在改的组件，不全量重构）。

### 2.3 空态 / 加载态 / 错误态三态规范

现状：空态仅个别键（`lb.empty`），多数列表为空时白板；加载依赖"loading"文字；错误只有 toast。

| 态 | 规范 | i18n 键约定 |
|---|---|---|
| 空态 | 图标(emoji 即可) + 一句话 + 一个动作按钮。"暂无已结算对局"→"🏁 还没有战绩 —— [开一局]" | `empty.<域>` + `empty.<域>.cta` |
| 加载态 | 列表用 3 行骨架占位（CSS 渐变动画，一个 util class `.skeleton`）；按钮内 loading 用"…"后缀 + disabled | — |
| 错误态 | 区块级错误不空白：显示 `err.network`/具体 message + [重试] 按钮（重试=重调该区块 load 函数） | 复用 `err.*` |

落点：app.js 加 `renderEmpty(el, key)` / `.skeleton` 工具，各视图逐步接入；优先接入首页榜单、历史、房间列表三处最常见空白。

## 3. 全局反馈、通知与微交互规范

### 3.1 toast 分级（现状单样式 3 秒，全部同权重）

```js
toast(msg)            // info: 默认, 3s, 中性色
toast.ok(msg)         // 成功: 2.5s, 绿边, 用于 成交/保存/领取
toast.warn(msg)       // 警告: 4s, 黄边, 用于 预算将尽/接近强平线/挂单自动撤销
toast.err(msg)        // 错误: 5s, 红边 + 不自动消失可手点关闭(操作失败需要被读完)
```
实现：toast 元素加 class 即可，API 向后兼容（现有 40 处 `toast(` 调用不改，新代码按语义选级别）。

**交易反馈映射**（模块 3 任务 1）：
- 下单成功 → `toast.ok`（含成交价与股数，已有文案升级级别即可）
- 业务拒绝（封板/T+1/现金不足）→ `toast.warn`（规则拒绝不是"错误"，黄色降低挫败感）
- 系统错误（5xx/网络）→ `toast.err` + 文案带"可重试"暗示
- 挂单成交/自动撤销 → tick 返回已有 filledOrders/autoCancelled，当前混在一条提示里 → 拆两条：成交 `toast.ok`、撤销 `toast.warn` 并写明原因（"止损单已撤销：持仓不足"）

### 3.2 异步任务反馈

| 场景 | 现状 | 优化 |
|---|---|---|
| 回测/调参 | 按钮 disabled | 按钮文字变"回测中…"，>3s 时按钮下方细字"网格调参约需 10~30 秒"（预期管理比进度条便宜且够用） |
| 结算 | 即时 | 结算弹窗入场 300ms 渐入，收益率数字滚动到位（≤600ms，prefers-reduced-motion 时关闭）——唯一值得花的动效预算 |
| AI 顾问流 | 已是 SSE 流式 | 保持；"thinking"占位已有 |

### 3.3 状态变更通知与通知中心（轻量版）

**原则：红点 > 站内条 > toast > 弹窗，能用低打扰就不用高打扰。弹窗只留两种：结算弹窗、不可恢复确认。**

- 奖励到账/藏品解锁/段位变动：当次会话内用 `toast.ok`；跨会话（上次离线期间发生的）进**站内通知条**——首页顶部一条可关闭横幅"上次离线后：每日任务已刷新 / 新藏品 ×1"，数据来源都是现有接口（points/relics 状态对比 localStorage 快照），不建通知表。
- 红点规范：导航项红点只表达"有未读的新内容"（任务可领取/新藏品），点进即消；红点状态存 localStorage（按内容 hash），不进后端。
- 赛季临近结束：首页横幅位复用，"本赛季 N 天后归档"（纯前端按月末倒数）。
- **禁止**：进入页面即弹营销式弹窗；同屏多 toast 叠加（队列化，最多同屏 1 条，后续排队）。

## 4. 情境式新手引导与金融术语词典

### 4.1 分层情境引导（替代一次性全量引导）

现状：onboarding 一次性旗（app.js:3061），错过不再出现。改为**事件触发 + 每条只出一次 + 可重看**：

| 触发时机 | 引导内容（一条一句话，气泡指向目标元素） |
|---|---|
| 首次进入对局页 | "每天只有一个决定：买、卖、或什么都不做 → 点「下一天」看结果" |
| 首次持仓过夜 | "现金会生利息，持仓会随收盘价波动——都在上方资产栏" |
| 首次亏损日 | "别急着割——试试挂一张止损单，跌破价位自动卖出（指向挂单区）" |
| 首次见到涨停/跌停（realRules） | "封板了：今天买不进/卖不出，这是 A 股真实规则" |
| 首次打开竞技模式 | "神秘标的 + 虚拟日期 = 没人能查答案，拼的是纪律" |
| 首次结算 | "复盘比结果重要：看看你和「死拿不动」基准的差距" |
- 实现：`guides.js` 一个 IIFE，`guideOnce(key, targetSel, textKey)`，localStorage 记已读 key；气泡复用现有弹窗样式缩小版。头部 ❓ 按钮 = 清空已读 key 重新激活。
- 规则：同屏同时最多 1 条；用户连续关闭 2 条后静默 24h（尊重"别教我"信号）。

### 4.2 术语悬浮词典（扩展现有 glossary）

现状：glossary.js 已有词典与 `linkifyTerms`（转义安全）。优化：
1. **覆盖面审计**：对照 §5 风险文案与复盘指标，补齐缺口词条：回撤、夏普、滑点、流动性、杠杆、强平、T+1、前复权、基准、定投（已有的不动）。
2. **接入点扩展**：复盘指标表、开局高级设置、挂单类型下拉的 label 全部过 linkify（目前主要在 wiki/学堂域）。
3. 交互统一：悬浮 300ms 出卡片（桌面）/ 点击词出底部卡（触屏）；卡片内"去学堂详解 →"链接对应课程锚点。

### 4.3 新手保护机制（不改数值，只改信息与默认值）

- 开局默认不开杠杆、不开真实规则（已是），高级开关折叠（§1 干预 1）。
- **满仓预警**：新手（前 3 局）单笔买入会用掉 >80% 现金时，确认条附加一句"全押会失去调仓余地——确定吗？"（文案级，不拦截）。
- 强平教育：进阶模式开启瞬间弹一次性说明"净值归零会被强制平仓"，并在保证金率 <150% 时状态栏变黄、<120% 变红（已有 marginRatio 数据，只加配色阈值）。
- 首局结算的安抚分支见 §1 干预 2。

### 4.4 新手任务 → 能力试炼（文案与顺序重排，不改任务系统）

现有每日任务位（结算/每日挑战/宝箱等）保持；把"新手期任务文案"从"完成 1 次结算 +30"改为试炼叙事链：
```
试炼① 活下来: 完成一局且净值不归零
试炼② 会止损: 一局内用一次止损单且被触发
试炼③ 跑赢躺平: 收益率超过买入持有基准
试炼④ 看懂自己: 查看一次复盘偏差诊断
试炼⑤ 出师: 任意难度战胜 AI
```
落点：i18n 文案 + 任务达成判定复用现有结算数据（beatHold/beatAi/诊断查看事件），无新表。

## 5. 用户预期管理与文案规范

### 5.1 机制透明三板斧（固定位置，不弹窗）

1. **模拟声明**：页脚常驻一行 + 开局卡小字："行情为历史数据回放/模拟数据，收益不代表真实投资能力，本游戏不构成投资建议。"（双语）
2. **规则可查**：学堂/wiki 增三页静态说明（纯文案）：AI 对手是什么（各难度用什么模型、它看不到未来）、积分怎么算（基础/胜 AI/连胜/任务，与 PointsService 口径一字不差）、藏品掉落规则（条件掉落就写条件，概率掉落必须写真实概率）。**口径以代码为准，文案与代码不一致按 bug 处理。**
3. **扰动事件标识**：事件回放/新闻事件卡片角标"历史事件回放"，避免被当成实时新闻。

### 5.2 风险提示文案规范（统一模板，固定位置）

| 位置 | 文案模板 |
|---|---|
| 开局卡（开真实规则/杠杆时） | "⚠ 进阶模式允许做空与透支：净值归零将被强制平仓" —— 开关旁行内文字，非弹窗 |
| 杠杆首次开启 | 一次性确认弹窗（唯一允许的风险弹窗），正文 ≤3 行 + 术语可点词典 |
| 竞技开局 | "竞技局使用匿名标的与虚拟日期，结算后揭晓" |
| 结算分享卡 | 自动附"模拟交易成绩，不构成投资建议" |

文案三原则：说人话（禁"由于系统原因"）、给出路（每条错误提示带下一步动作）、不吓唬（风险提示讲机制不渲染恐慌）。

## 6. 用户行为埋点与分群分析模型

> 现状：**零埋点**。方案按"最小可用"设计：前端 `qsTrack(event, props)` → `navigator.sendBeacon` 批量 POST `/api/track`（游客按匿名会话 id）→ 单表 `ux_events(id, user_id?, anon_id, event, props_json, created_at)`，无第三方 SDK。隐私：不采输入内容，只采动作与视图；props 禁含用户文本。

### 6.1 核心转化漏斗（埋点清单）

```
F1 激活漏斗: view_home → start_click → game_started → first_tick → game_settled(首局)
F2 竞技漏斗: view_daily → daily_started → daily_settled → view_board(次日回访=留存钩子)
F3 学习漏斗: settle_viewed → diagnosis_viewed → academy_opened(败因桥点击) → course_done
F4 社交漏斗: settle_viewed → challenge_created → room_joined(被邀方) → room_played
```
每个事件带 `{view, mode, dayIndex?, source}`。漏斗健康基线先采集两周再定目标；明显断崖（相邻步转化 <40%）即列优化项。

### 6.2 用户分群（按 14 天行为自动归档，SQL 视图即可）

| 分群 | 判定 | 运营含义 |
|---|---|---|
| 一次性游客 | 仅 1 个会话日且无结算 | 看 F1 哪步断的 |
| 浅度学习者 | 学堂/研究所事件 > 对局事件 | 推"边学边练"桥 |
| 休闲对战玩家 | 有结算、无竞技、周活 1~2 天 | 推每日挑战钩子 |
| 重度策略玩家 | 回测/调参/限制条件/HELL 任一高频 | 推同题约战与新面孔榜 |

### 6.3 留存/活跃/退出指标

- 留存：次日/7 日/30 日（按 anon_id∪user_id 合并口径，注册认领游客时合并历史）。
- 活跃：周对局数、周竞技参与率、复盘打开率（settle→diagnosis 转化）。
- 退出行为：`session_end` 前最后一个事件分布——**高频"最后动作"就是流失触点排行榜**；对局中途弃局率（started 无 settled 且 7 天未续）按 dayIndex 分布定位"无聊拐点"（验证 §1 J5 的第 8~15 天假设）。

### 6.4 自动分析规则（cron 周报，输出到 docs/ux-weekly/）

```
R1 漏斗断崖: 相邻步转化率 < 40% 且样本 ≥50 → 列为 P1 优化项
R2 弃局拐点: 弃局 dayIndex 分布的众数 → 建议在该天前注入微目标(§1 干预4)
R3 首败流失: 首局负收益用户的次日留存 vs 首局正收益 → 差距 >15pp 则加强安抚分支
R4 引导有效性: 看过情境引导 vs 没看过的同步骤转化差 → 无差异的引导条目删除(减噪)
R5 提示疲劳: 单会话 toast >15 条 → 该视图提示降噪排查
```
