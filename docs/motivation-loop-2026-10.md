# QuantSim 游玩动机 & 沉浸感专项优化方案（解决"打开页面不想玩"）

> 核心判断：QuantSim 不缺系统，缺的是**把系统接成循环**。结算时已计算玩家风格标签（`GameBenchmarks.styleTag`）、偏差诊断已有逐局行为数据（`BiasReport`）、休闲小游戏已有一排（tape 盯盘/bubble/buydip/newsjudge/option/richman）、任务位/藏品/生涯页/分享卡全部在库——它们各自孤立，玩家感知不到"我在一个游戏里成长"，只感知到"一堆工具"。
> 本方案 95% 的内容是**重组与文案化现有数据**，标 ⚙ 的少数项需要小后端改动（均不触撮合/结算内核）。与 `docs/ux-optimization-2026-10.md`（体验层）、`docs/copy-style-guide.md`（文案）、`docs/product-innovation-2026-10.md`（玩法方案）互补不重复。

## 1. 玩家三层动机闭环设计

### 1.1 玩家打开页面那 3 秒的心理账

工具感的根源：首屏回答的是"数据在哪"，而玩家潜意识在问三个问题——**"今天有什么新的？""我上次到哪了？""现在玩一把要多久？"** 三问都没答案，就关页。闭环设计围绕让每一屏回答这三问。

### 1.2 三层目标结构

**短期（1~5 分钟，打开即有）**
| 机制 | 设计 | 复用 |
|---|---|---|
| 今日三签 | 每天 3 个轻任务替代单一签到：玩一把极速局 / 对局里做一次止损 / 猜对一次涨跌（任选其二完成即领）| 任务位系统（UserPoints TASK_*，⚙ 加 2 个位） |
| 单局即时微反馈 | 对局内每个"好动作"即时一行小字+微量积分（§3.1 清单） | 前端判定 + 结算统一入账（防刷见 §8） |
| 极速局 | "3 分钟来一把"：5 个交易日窗口的迷你对局，首页一键进 | ⚙ GameSession 加 `totalTicksOverride`（单列小迁移），撮合结算完全复用 |
| 藏品碎片 | 输局也掉"碎片"（×3 合成一件普通藏品），掉落条件=行为不=胜负 | relics 系统 ⚙ 加碎片计数 |

**中期（单局/当日）**
| 机制 | 设计 | 复用 |
|---|---|---|
| 本局挑战 | 开局随机抽 1 条（最大回撤 <8% / 跑赢定投基准 / 全程不满仓 / 用一次挂单成交），结算判定，达成得**本局勋章**进履历 | 判定数据全部已有（riskMetrics/基准/流水），结算时纯计算 |
| 每日挑战钩子 | 结算页预告"明日挑战 {行业} 场，今日榜首 +{0}%"——给明天一个具体期待 | daily 现有数据换个说法 |

**长期（赛季）**
- 保持现有：段位/赛季榜/稀有藏品/生涯档案。唯一改动：**把长期目标可视化到短期动线里**——首页"赛季进度条"一行（当前段位 → 下一段位还差 N 分），让长线目标每天被看一眼而不是赛季末才想起。

### 1.3 "输局也有收获"的奖励矩阵（关键）

| 结局 | 拿到什么 | 原则 |
|---|---|---|
| 赢 | 积分（现有）+ 本局挑战勋章（若达成） | 胜利奖励**不加码**——赢本身就是奖励 |
| 输但完成本局挑战 | 挑战勋章 + 碎片 ×1 | 挑战与胜负解耦：回撤控制好的输局比乱赢更值得奖励 |
| 输且没完成挑战 | **复盘奖励**：查看完偏差诊断 + AI 操盘日志后领"学费回收"微量积分 + 碎片概率 | 把"输了"转译成"拿到了一份只有输才给的数据"——复盘是输家限定内容 |
| 弃局 | 无 | 唯一零收获的结局是不打完——奖励结构本身劝完赛 |

文案口径（对齐 copy-style-guide §1.2）：输局结算首行永远是"本局带走了什么"，不是红色收益率。

## 2. 首页 + 大厅内容与信息架构重构

### 2.1 首页首屏（从"数据面板"到"出发大厅"）

```
┌──────────────────────────────────────────┐
│  [你的临时目标]  今日三签 ●●○   赛季进度 ▓▓▓░ 距白银 120 分
│
│       ┌──────────────┐   ┌──────────────┐
│       │  ⚡ 极速局     │   │  🏆 每日挑战   │      ← 两个大按钮, 页面 C 位
│       │  3 分钟一把    │   │  全服同题竞技  │
│       └──────────────┘   └──────────────┘
│  继续上局 ▸ 第 7 天 (有进行中对局时置顶替换极速局)
│
│  [动态条] 「夜行者 刚刚在每日挑战打出 +6.2%」 (轻量滚动, §2.2)
├──────────────────────────────────────────┤
│  ▾ 排行榜 / 任务列表 / 积分商城 (折叠, 数据参考层)
└──────────────────────────────────────────┘
```
- 行情数据、全量榜单全部移出首屏（折叠或进二级）——与 ux-optimization §2.1 的"单一主 CTA"合并执行，主 CTA 从一个升为"两入口 + 续局"组。
- 三问对答：今日三签（有什么新的）/ 续局+赛季条（我到哪了）/ 极速局（多久一把）。

### 2.2 动态社交播报（轻量，防刷屏）

- 数据源：现有公开数据的事件流——每日榜前排变动、藏品解锁、段位晋升。⚙ 后端一个只读接口 `/api/feed`（查最近 N 条已结算记录拼装，无新表；缓存 60s）。
- 展示规则：首页单行滚动条，10 秒一条，最多展示 5 条后停（不无限滚）；可整条关闭（localStorage 记忆）；用户名走 PublicNames 脱敏——**不泄露可定位信息，竞技局不带标的与窗口**（防剧透红线）。

### 2.3 双入口定位

| 入口 | 定位 | 配置 |
|---|---|---|
| ⚡ 极速局 | 低压力随手玩：5 天窗口、EASY AI、休闲规则、**不进榜**只记任务/碎片 | ⚙ totalTicksOverride=5 |
| 🏆 天梯（每日挑战/房间/赛季） | 正式竞技：现有体系不动 | — |

极速局不进榜是平衡关键：防止短窗口方差刷榜，也让它彻底零压力。

## 3. 对局内情绪反馈与里程碑机制

### 3.1 好动作即时反馈清单（前端判定，一行小字 + 轻音效）

| 触发 | 文案（示例） |
|---|---|
| 止损单被触发且避免了更深跌幅（次日价更低） | 「止损救了你一次：少亏 {0}%」 |
| 分批建仓（同向 ≥2 笔且间隔 ≥2 天） | 「分批进场，老手动作」 |
| 空仓躲过大跌日（当日 -3%+ 且无持仓） | 「这根大阴线与你无关」 |
| 浮盈兑现（止盈单成交） | 「落袋为安 +{0}%」 |
| 连续 3 天管住手（有现金但未追高） | 「纪律值 +1：三天没追高」 |
- 全部由前端用已下发数据判定（K 线+流水+挂单回执），**不调接口**；每局每类最多触发 1 次（防复读机）；错误动作**不实时批评**——留给结算诊断（对局中批评打断心流且惹人烦）。

### 3.2 阶段里程碑（1/3、2/3 进度）

tick 返回已有 daysElapsed/totalTicks，前端在 1/3、2/3 各弹一次 3 秒横幅：
「第 {0}/{1} 天 · 收益 {2}% · 本局挑战：回撤 {3}%/8%（还稳）」——只报进度与挑战距离，不建议操作（建议是顾问的事，边界清晰）。

### 3.3 失败保护

§1.3 奖励矩阵已覆盖；补一条**强平特护**：进阶模式被强平时，结算页置顶"强平复盘卡"（触发日杠杆率曲线 + 一句"杠杆在 {0} 天把波动放大到了 {1}%"），并解锁隐藏藏品碎片「爆仓纪念章」——把最挫败的时刻变成稀有收集品（输得惨 = 拿到别人拿不到的东西）。

### 3.4 微型剧情事件

新闻事件系统已有（NewsService，竞技局不下发的防剧透规则不动）。增强：
- 事件卡文案三段式：一句历史现场 + 当日盘面反应 + 「你的持仓：{受影响}」——第三段是沉浸关键（事件与"我"有关）。
- 明日快讯（upcomingNews 已有"要不要先调仓"的决策时刻设计）加倒计时感文案：「明早开盘前，你还有一次调仓机会」。

## 4. 藏品 & 临时称号体系

### 4.1 藏品双轨

| 轨 | 获取 | 定位 |
|---|---|---|
| 赛季排名限定 | 赛季榜/段位（现有） | 稀缺性来自竞技 |
| **对局挑战限定** | 高难度行为挑战，与胜负无关：「教科书止损」（一局 3 次止损全部正确）、「逆行者」（抄底后 5 天内 +10%）、「铁手」（限 5 笔模式跑赢持有基准） | 稀缺性来自操作难度——输家也能拿 |
- 判定全部在结算时用已有流水/指标计算（⚙ 结算尾部一个 AchievementCheck 纯函数，见 §8.2）。

### 4.2 收藏故事墙

藏品详情从"图+描述"升级为"图+描述+**解锁快照**"：解锁那局的 对局日期/标的（竞技局已揭晓）/收益曲线缩略图/当时达成条件的数值。⚙ relics 解锁记录加 sessionId 外键，渲染复用 sharecard 的曲线绘制。文案规范沿用 copy-style-guide §4.7（一件物品+一个瞬间，禁直接写教训）。

### 4.3 临时局内称号

- 对局中达成条件即时点亮（§3.1 同一套判定）：「狙击手」（单笔 +5%）、「守门员」（回撤未破 5%）、「冷静者」（大跌日无操作）。
- 本局生效：显示在对局页玩家名旁 + 结算页列出本局全部称号 + 写入生涯履历（career 页已有逐局记录位）。
- 房间对局中**对其他玩家可见**（战况表名字旁小图标）——称号的社交展示才是它的全部价值。

## 5. 学堂能力树改造：学习 = 解锁信息能力

**原则：解锁的是"看到更多"，永远不是"赚得更多"**（§8 平衡红线）。

| 课程/能力节点 | 解锁的对局内工具 | 实现 |
|---|---|---|
| 均线基础 | K 线图 MA5/MA20 叠加开关 | 指标数据已下发，前端开关而已——**把现有功能变成解锁物** |
| 波动与风险 | 状态栏实时回撤/波动率小组件 | 同上，数据已有 |
| 动量风控 | 「追涨检测」：买入时若当日涨幅 >3% 显示提示角标 | 前端判定 |
| 挂单进阶 | 移动止损单类型解锁 | 前端菜单项 gating（后端不拦，防作弊无意义——这是帮助不是优势） |
| 行为金融 | 结算偏差诊断的"历史趋势对比"扩展视图 | biasprofile 已有 |

**败因→能力桥**（闭环点睛）：结算诊断出"追涨"→ 诊断卡尾部「解锁【动量风控】，下次买入时它会拉你一把 → 去学堂（2 分钟）」。学习动机从"任务叫我学"变成"我刚被坑了所以想学"。
- 实现：学堂完成状态已存（userProgress），前端按完成键 gating 各工具；零后端改动起步。

## 6. 自动交易者人设系统

- **底料已有**：`GameBenchmarks.styleTag` 每局已算风格标签，BiasProfile 有跨局行为趋势。缺的只是聚合与展示。
- 人设卡：近 10 局 styleTag 众数 + 2 个特质维度（换手率高低、风险偏好）映射到四象限人设：**价值猎手 / 波动游击手 / 风控铁壁 / 事件博弈者**；每局结算后更新，"人设进化"时结算页播报（「你从 波动游击手 进化为 价值猎手」）。
- 展示位：个人主页人设卡（主位）+ 房间战况表头像旁人设角标 + 分享卡（sharecard 已有生成器，加一行人设）。
- 防标签焦虑：人设文案全部正面中性（没有"韭菜型"），变化用"进化/转型"不用"退步"。
- 实现：⚙ 一个只读聚合接口或前端用 me/games 现有数据直接算（优先后者，零后端）。

## 7. UI 视觉层级重构（三层分区）

```
游戏叙事层  目标/挑战/称号/动态播报/人设 —— 占据 C 位与首屏
核心操作层  开局/买卖/下一天/挂单 —— 大按钮, 固定位置, §7.4 密度规范
数据参考层  表格/指标/历史 —— 默认折叠或二级页, 需要时一键展开
```
- 执行手段与 ux-optimization §2 共用（--sp-* 阶梯、单主 CTA、三态规范），本方案追加两条氛围规则：
  1. **大数字仪式感**：收益率/积分变动用 28px 大字 + 600ms 滚动到位（唯一动效预算，prefers-reduced-motion 关闭）；
  2. **留白即高级**：卡片间距从拥挤网格改 12px 统一间隙，每屏卡片数 ≤4；装饰性图形只用现有 emoji 图腾体系，不引图片资源（无构建站的克制）。
- 空态全部变"邀请"：无藏品 →「档案馆还空着。第一件藏品最容易：打完任意一局」+按钮；无战绩 → 同理（接 ux-optimization §2.3 的 renderEmpty 工具）。
- 用户红线重申：**禁紫色系新增 UI；`.header-tools` 桌面单行横排不动**。

## 8. 平衡性约束与后端性能评估

### 8.1 公平红线（硬规则）

1. 一切新增产出（称号/勋章/碎片/人设/能力解锁）**零收益加成、零信息优势**——能力树解锁的信息全部是本来就下发给所有人的数据的展示开关（§5 表格可核）。
2. 极速局不进任何榜；局内微反馈积分走任务位封顶（单日上限=现有任务体系量级），**不按次数线性发放**——否则"反复止损刷积分"变成新刷分口（对照审计 P0-1 教训）。
3. 碎片/藏品掉落条件服务端判定（结算时），前端只做展示——前端判定的即时反馈（§3.1）只给文案与音效**不给积分**，积分統一结算时服务端复核后入账。
4. 动态播报不泄露竞技局标的/窗口（BlindDates 口径覆盖 feed 接口）。

### 8.2 后端压力评估

| 新增 | 时机 | 成本 |
|---|---|---|
| 本局挑战/勋章/碎片判定 | **结算事务尾部纯计算**（流水与指标已在内存，一次遍历） | 单局毫秒级，不碰交易主链路（tick/trade 零改动） |
| /api/feed | 只读查询 + 60s 缓存 | 可忽略 |
| 极速局 | totalTicksOverride 一列 | 结算/撮合逻辑零改 |
| 人设聚合 | 前端算 me/games 现有响应 | 零后端 |
- 不采用"异步任务队列"——单实例下结算内同步算完（毫秒级）比引入队列设施更简单可靠；若未来判定逻辑膨胀超 50ms 再拆（届时按审计 C1 事务规范拆 REQUIRES_NEW 后置步骤）。

## 10. 用户心理预期与挫败感防控

1. **奖励预告先于奖励**：开局卡展示本局挑战与可得勋章（预期建立），结算兑现——比惊喜更重要的是"我知道我在为什么玩"。
2. **挫败三阀门**：输局首屏说收获不说亏损（§1.3）；强平给限定收集品（§3.3）；连输 3 局触发一次性提示「要不要去极速局找找手感？」（降级出口，不是嘲讽）。
3. **防奖励通胀**：称号/勋章数量封顶（每类挑战一个赛季最多重复计 3 次进履历），稀有藏品严格双轨不混发——奖励一旦人人皆有，动机循环整体失效。
4. **防打扰回路**：所有新增弹层遵守 ux-optimization §3.3 降级原则与"连续关闭静默"；微反馈每局每类 1 次；玩家在设置可一键关"氛围层"（关后=今天的工具风——把选择权给高阶玩家，而不是替他们决定）。
5. **诚实边界**：动机设计不碰付费、不做 FOMO 倒计时营销、概率公示（copy-style-guide §4.7「档案馆不骗人」）——信任是留存的地基，短期钩子不值得透支它。
