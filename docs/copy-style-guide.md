# QuantSim 全站文案风格规范 + 示例库

> 基线盘点：`i18n.js` 现有 **1795 个中文键**（en 对照同量），文案底子好的部分要保持——AI 结算嘲讽（`settle.taunt.*`）、藏品描述（`relic.*.d`）已经是目标风格的范例；主要问题是**错误提示技术腔**、**各域语气不一**（有的像银行 App 有的像游戏）、**长句堆叠**。
> 本文档 = 规范（§1–3）+ 重点页面改写示例库（§4）+ 落地机制（§5）。所有改写须中英双份走 `t()`，这是站点承诺。

---

## 1. 全局语气与用词规范

### 1.1 人设一句话

**"懂行的老朋友坐在你旁边看盘"**——专业（术语准确）、松弛（不端着）、护短（输了先讲原因不嘲讽玩家——嘲讽是 AI 角色的台词，系统文案永远站玩家这边）。

### 1.2 语气三轴（写任何文案前先定位）

| 轴 | 规则 |
|---|---|
| 专业度 | 金融术语**不回避不滥用**：正文用准确术语，首次出现的术语必须是 glossary 可点词（悬浮解释），禁止生造词替代（"回撤"不写成"跌下去的幅度"——通俗解释放词典里，不占正文） |
| 游戏感 | 动词优先、短句、有画面："开局" 不是 "创建会话"；"揭晓" 不是 "显示标的信息"。emoji 只用于**状态图腾**（🎭揭晓/🏁结算/⚠风险），一句话最多 1 个，表格与错误文案禁用 |
| 情绪 | 赢：克制地热（"漂亮" > "恭喜您获得胜利"）；输：先归因后鼓励，禁止感叹号；风险：讲机制不渲染（"净值归零将被强平" ✓，"小心血本无归！" ✗） |

### 1.3 用词表（强制统一，全站别名清零）

| 统一用 | 禁用别名 |
|---|---|
| 对局 | 游戏局、会话、session |
| 开局 / 结算 | 创建对局 / 完成结算、清算 |
| 下一天 | 推进、tick、下一交易日（按钮上） |
| 标的 | 股票（泛指时）、票 |
| 净值 | 总资产（进阶模式语境） |
| 积分 | 金币、点数 |
| 藏品 | 收藏品、徽章 |
| 神秘标的 | 隐藏股票、匿名标的 |

数字规范：金额千分位（`fmtMoney` 已做）；百分比保留 2 位；"第 {0} 天"不写"Day{0}"（中文界面）。

### 1.4 句式红线

- 单句 ≤ 22 个汉字；一条 toast ≤ 1 句；弹窗正文 ≤ 3 行。
- 禁被动腔与系统腔："您的请求已被系统处理" → "搞定"。
- 禁"请"字开头连用（一屏最多一个"请"）；禁"哦/呢/啦"卖萌尾字（AI 角色台词除外——那是它的人设）。
- CLAUDE.md 既有纪律：**图形和按钮能说明的，不加解释性文字**——先删字，再润色。

## 2. 三层文案体系（主文案 / 辅助小字 / tooltip）

| 层 | 职责 | 规格 | 示例 |
|---|---|---|---|
| 主文案 | 让用户知道"这是什么、点了会怎样" | ≤10 字，动词开头优先 | 按钮「下一天」；标题「结算复盘」 |
| 辅助小字 | 补充边界条件、当前状态 | ≤22 字，muted 色，可被高阶模式隐藏（见 §5.2） | "挂单在次日按开盘价与触发价择优成交" |
| tooltip / 词典卡 | 术语解释、计算口径 | 2~3 句：是什么 + 在本游戏里意味着什么 + （可选）去学堂链接 | 见 §4.6 |

**分层铁律**：同一信息只出现在一层。按钮叫"止损单"（主），小字讲触发规则（辅助），"止损"这个词的金融含义在词典（tooltip）——三层各说各的，不重复。

## 3. 反馈文案模板（与 UX 报告 §3.1 toast 四档对齐）

| 档 | 模板 | 要点 |
|---|---|---|
| 成功 ok | `{动作}{结果数字}` | 带数字才有确认感："买入 500 股 @ 10.00" 不是"操作成功" |
| 提示 info | `{状态变化一句话}` | 中性陈述，无感叹号 |
| 警告 warn | `{没发生什么}：{规则原因}` | **规则拒绝不是错误**："今天买不进：涨停封板（A 股规则）"——先说结果再给原因，语气是"规则如此"不是"你错了" |
| 错误 err | `{出了什么事}，{你现在能做什么}` | 必带出路："网络断了，稍后点重试" |

错误文案改造三步法（针对后端 `BusinessException` 文案与前端 `err.*`）：
1. **去技术名词**：用户看不到"请求体/校验/参数"这些词 → "填写的内容有问题，检查一下价格和数量"；
2. **指认现场**：报错必须说清是哪个输入/哪个动作（"触发价最多两位小数" ✓ 已达标，保持）；
3. **给出路**：限流 → "手速太快，歇 {0} 秒再试"；500 → "服务器开小差了，刚才的操作没有生效"（强调无副作用，安抚第一）。

## 4. 重点页面文案示例库（现状 → 改写，双版标注）

> 【新】= 新手友好版（默认）；【高】= 高阶精简版（见 §5.2 开关）。未标注 = 两版共用。

### 4.1 首页

| 位置 | 现状风格问题 | 改写 |
|---|---|---|
| 主 CTA | — | 「继续上局 ▸ 第 {0} 天」/ 无进行中对局时「开一局」 |
| 游客提示 | 缺失（流失点 J2） | 辅助小字：「游客战绩会保留——注册后一键认领」 |
| 签到 | "每日签到领取积分" | 【新】「今日报到 +{0} 分」【高】「签到 +{0}」 |

### 4.2 房间大厅

| 位置 | 改写 |
|---|---|
| 空态 | 「还没有房间。建一个，把房间码甩给朋友」+ 按钮「创建房间」 |
| 创建成功 | ok:「房间 {0} 开好了，房间码已复制」 |
| 加入失败（满员） | warn:「这间满了：{0}/{0} 人。要不自己开一间？」 |
| 规则小字 | 【新】「同一行情窗口，各打各的，到期一起揭榜」【高】隐藏 |

### 4.3 交易面板与订单提示

| 场景 | 现状 | 改写 |
|---|---|---|
| 买入成功 | "买入 {0} 股成功" | ok:「买入 {0} 股 @ {1}」（价格入文案，确认感） |
| 现金不足 | "现金余额不足（含手续费 {0}）" | warn:「现金不够：这笔连手续费要 {0}」 |
| 涨停拒买 | （后端文案直出） | warn:「今天买不进：涨停封板」+ 词典词「涨停」 |
| T+1 拒卖 | 同上 | warn:「今天买的 {0} 股明天才能卖（T+1）」 |
| 挂单回执 | — | ok:「止损单挂好了：跌破 {0} 自动卖出 {1} 股」【高】「止损 {0} × {1} 已挂」 |
| 挂单自动撤销 | （混在 tick 提示里） | warn:「止损单已撤销：触发时持仓不足」 |
| 笔数预算 | "剩余可交易 {0} / {1} 笔" | 保持（已达标），耗尽时 warn:「本局 {0} 笔额度用完了——这就是纪律的代价与意义」 |

### 4.4 结算复盘

| 位置 | 改写 |
|---|---|
| 赢 AI | 主标题「+{0}%，压过了 {1}」副句【新】「赢在哪？看看你和它的操作差异 ↓」 |
| 输且首局 | 主标题不写负收益率置顶，先写「击败了买入持有基准 {0}%」或「第 1 局，交学费很正常」；副句「AI 做对了什么？看它的操盘日志 ↓」 |
| 一句话诊断 | 「本局最大的坑：{偏差名}——{一句人话解释}」如「追涨：3 次在放量大阳线次日追入，2 次被套」 |
| AI 嘲讽 | **保持现有**（`settle.taunt.*` 是全站文案标杆） |
| 揭晓 | 保持「🎭 揭晓！本局标的是 {0}（{1}）」 |

### 4.5 学堂 / 任务（试炼叙事，对齐 UX 报告 §4.4）

| 现状风格 | 改写 |
|---|---|
| "完成 1 次结算 +30" | 【新】「试炼 · 活下来：打完一局，净值不归零」奖励小字「+30」 |
| "战胜 AI 对手" | 「试炼 · 出师：任意难度，赢 AI 一次」 |
| 课程完成 | ok:「这节过了。下一个坑：{下一课名}」 |

### 4.6 词典卡模板（tooltip 层）

```
【回撤】从最高点跌下来的幅度。
本局口径: 资金曲线峰值到谷值的最大跌幅。
回撤 20% 需要涨 25% 才能回本——这就是为什么要控制它。   [去学堂详解 →]
```
三段式：一句定义 / 本游戏口径 / 一个反直觉事实（记忆钩子）。杠杆、滑点、流动性、T+1、前复权同模板补齐。

### 4.7 赛季公告与藏品（沉浸感润色）

- 赛季命名叙事：赛季号 + 一个历史行情绰号——「S2026-10 · 多头的十月」；归档公告模板：「{赛季名} 已归档：{N} 位玩家留下战绩，最高 {0}%。新赛季，榜单清零，故事重来。」
- 藏品**保持现有水准**（"油墨里全是恐慌"是范例），补齐规范：描述 = 一件具体物品 + 一个历史瞬间 + ≤24 字；禁直接写教训（教训放对应学堂课，藏品只负责氛围）。
- 掉落说明（预期管理，对齐 UX 报告 §5）：条件掉落写明条件原文；概率掉落写真实概率，文案「档案馆不骗人：概率就是 {0}%」。

### 4.8 错误提示重构对照表（err.* 与高频后端文案）

| 现状 | 改写 |
|---|---|
| 请求失败 (HTTP {0}) | 「服务器没接住这个请求（{0}），刚才的操作没有生效」 |
| 响应格式异常 | 「服务器回了句听不懂的话，稍后再试」 |
| 请求过于频繁, 请稍后再试 | 「手速太快，缓一分钟再来」 |
| 登录状态已失效, 请重新登录 | 「登录过期了，重新登录就好——对局进度都在」 |
| 该用户名已被注册, 请登录后再玩 | 「这个名字有主了：是你的话直接登录，不是就换一个」 |
| 结算日行情缺失 | 「这天的行情数据缺了，暂时结算不了——我们会尽快补数」 |

## 5. 落地机制

### 5.1 执行方式

- 文案全部改在 `i18n.js`（中英同改），**零 Java 改动优先**——后端 BusinessException 文案被前端 toast 直出，改造方式：高频后端文案在前端按 message 映射改写**不可行**（禁止依赖文案子串判断，kb R4 反面模式）→ 正确做法是直接改后端文案源头（BusinessException 构造处），按 §4.8 对照表小步提交。
- 改写顺序按曝光频率：交易面板 → 结算 → 错误 → 首页 → 任务 → 其他；每批一个 PR，`ui_check.py` 把关键完整性（缺键/死键自动报错）。

### 5.2 新手版 / 高阶版双版机制（不建第三套字典）

- **主文案永远单套**（按钮/标题双版会让教程和玩家对不上话）。
- 双版只作用于**辅助小字层与情境引导层**：`<body data-copy="pro">` 时 `.copy-hint` 类隐藏 + 少数标注【高】的键用 `key.pro` 后缀覆盖（t() 取值时先查 `${key}.pro`，一行改动）。
- 开关位置：设置区「极简文案」，默认关；玩家结算 ≥10 局后弹一次 info 提示可开启（高阶身份确认）。

### 5.3 文案 PR 自查清单

```
- [ ] 中英双份, ui_check 0 error
- [ ] 过 §1.3 用词表 (无别名) 与 §1.4 句式红线 (长度/感叹号/系统腔)
- [ ] 错误类: 有现场 + 有出路; 警告类: 规则语气非指责语气
- [ ] 术语首次出现是 glossary 可点词
- [ ] 风险/概率/口径类文案与代码口径一致 (不一致按 bug 处理)
```
